# taiwan-traditional-chinese 實測結果

測試日期 2026-08-10。方法、限制與重跑指令見 [README.md](./README.md)。

**結論：這是術語與行文規則的執行器，不是寫作品質提升器。** 術語替換與去 AI 味有明確效果，而且不會誤傷本來就正確的台灣用語；「文章整體變好看」這件事沒有資料支持。

## 一、術語替換

12 題，分三層：常見詞 1（代碼→程式碼，預期平手）、冷僻詞 7（要查表才會）、防守題 4（看起來像中國用語、其實是台灣正確用法，改了倒扣）。

| 模型 | 沒有 skill | 有 skill |
|---|---|---|
| 預設模型（Sonnet 級） | 9/12（冷僻詞 4/7） | **12/12（冷僻詞 7/7）** |
| haiku | 5–6/12（冷僻詞 0–1/7） | 2–12/12，不穩 |

預設模型的三個 MISS 是「位元模式」（應為位元型樣）、「核心映像」（應為核心映像檔）、「請勿追蹤」（應為不要追蹤），三個都是 `terms.csv` 的精確命中。差距來自查表，不是來自模型變聰明。

**防守題 4/4 出現在每一個 arm、每一次執行。** 七次執行零誤殺。術語表工具最大的風險是把對的改成錯的，這裡沒有發生。

## 二、去 AI 味

三篇長文，數違規次數除以中文字數。違規項目包含破折號密度、假對比（不是 X 而是 Y）、三項式排比、整句加粗、AI 套語。

| 模型 | 沒有 skill | 有 skill | 字數變化 |
|---|---|---|---|
| 預設模型 | 3.0／千字 | **0.0／千字** | 985 → 892（−9.4%） |
| haiku | 7.0／千字 | **0.0／千字** | 718 → 721（持平） |

haiku 的字數持平，代表零違規不是靠砍內容換來的。預設模型少了 9.4%，這個幅度可能有一部分是刪贅詞，也可能有一部分是內容變少，單次資料分不出來。

baseline 的違規類型：預設模型是假對比 2 次、整句加粗 2 次；haiku 是破折號 5 次、整句加粗 1 次。

## 三、整體文字品質（盲測）

三題生成任務：commit message、PR 描述、設定選項說明。兩個 arm 的輸出打散成 A／B，交給四位沒讀過本 skill 的評審，其中兩位看原順序、兩位看對調順序（檢查位置偏誤）。

| 題目 | 選到有 skill 的人數 |
|---|---|
| G1 commit message | 4/4 |
| G2 PR 描述 | 3/4 |
| G3 設定選項說明 | 1/4 |
| 合計 | 8/12 |

**8/12 不足以宣稱有效。** 隨機期望值是 6/12，單尾 p≈0.19。

G1 四人一致的理由是同一件事：題目要求中文，baseline 交了整行英文，沒答到題。這題贏的是「照規則做」，不是文筆。

G3 三人選 baseline，其中兩位在對調順序後仍然選它，所以不是位置偏誤。理由見下方缺口 1。

## 四、三個已知缺口

1. **規則寫了不等於會遵守。** G3 的 skill 版寫了「Component 樹」，而 SKILL.md 明列 `component 元件`。嵌在英文技術語境裡的詞最容易漏，這是 skill 輸掉 G3 的主因之一。
2. **haiku 級模型不可用。** skill arm 四次拿到 2、6、10、12。追工具軌跡看出分水嶺是 `lint_zhtw.py` 有沒有真的跑完並被採用，模型有時放棄查表直接輸出。已補 stdin 支援，補完後那次是 6/12，波動沒有收斂。對照組 baseline 三次是 5、6、6，穩定得多，所以不穩的是多步工具流程而不是題目。
3. **成本在工具呼叫次數，不在 token。** frontmatter 的 description 常時佔約 250 token 可忽略，SKILL.md 約 3,000 token，寫散文再加 prose-style.md 約 3,000。真正的代價是術語題那次追到的 12 次工具呼叫——慢，而且每一步都是可能斷掉的地方。

## 五、這些數字有多可信

1. **語氣計分是循環的。** `tone_score.py` 的違規清單來自 SKILL.md 和 prose-style.md，拿 skill 自己的規則評 skill 的產出，對 skill 有利。可信之處在於清單公開、可逐條核對，但不能宣稱中立。盲測那組不循環，也正是分數最難看的一組。
2. **baseline 不是完全乾淨的。** `--disallowed-tools` 擋掉了 skill 呼叫，但系統提示裡仍有各 skill 的 description 和 user CLAUDE.md。真實差距可能比帳面更大。
3. **每個 arm 大多只跑一次**（haiku 術語除外）。n=12 題加 3 篇長文，足夠說「示範」，不夠說「統計顯著」。

## 六、建議

**值得裝**：產出會留下來的中文——commit message、PR 描述、ADR、README、規格書、zh-TW locale 檔。搭配 Sonnet 以上的模型。

**不值得裝**：聊天回覆（skill 的 description 本身就排除了）、跑 haiku 的自動化流程、只是想讓文章寫得更好看。

**對同事的一句話**：它保證你的中文不會出現「組件」「數據」「落地」，也不會把「通過審查」誤改成「透過審查」。文章好不好看它管不了。
