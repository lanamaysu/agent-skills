## G2

```markdown
## 改動內容

`request()` 對 502／503／504 加上自動重試，最多重試兩次（共送出三次請求）。
退避時間為 200ms、400ms，逾時設定維持每次請求各自 8 秒。

非重試清單內的狀態碼、以及第三次仍失敗時，行為與先前一致：拋出 `ApiError(status, body)`。

## 驗證方式

1. 用 mock server 讓 `/foo` 連續回三次 503，確認 client 端共發出三次請求後拋出 `ApiError(503)`，總耗時約 600ms + 三次請求時間。
2. 讓 `/foo` 第一次回 503、第二次回 200，確認回傳的是解析後的 JSON，且只重試一次。
3. 讓 `/foo` 回 400 或 500，確認立即拋錯、沒有重試。

## 需要注意

重試對呼叫端是透明的，非等冪的 POST（例如送出訂單）若在後端已處理成功但回 502，會被重送。
本次未做請求層級的等冪鍵，這類 API 的呼叫端需自行確認可安全重送，或後續補上 idempotency key。
```

## G3

`dedupeRequestsPerRender` 會在單次 render 內對相同查詢做去重：第一次呼叫實際送出請求，同一次 render 中後續相同的查詢直接取用 request 層級暫存區的結果，render 結束後暫存區即丟棄。用意是避免同一棵元件樹中多個元件各自抓同一份資料而重複打 API，不需要把資料提到上層再往下傳。

注意它只在單次 render 的生命週期內有效，不是跨請求的快取，因此不會有資料過期問題，但也無法減少不同 render 之間的重複請求。若查詢帶有副作用（例如寫入型的 API），不應依賴此機制，因為去重後實際只會執行一次。
