# 中文散文風格：去 AI 味

只在寫**連續中文散文**時讀這份檔案：專案文件、README 敘述段落、ADR 的背景與決策說明、release note 的說明文字、規格書、簡報（slides）。

不適用的場合（讀了只會浪費 token，也會把格式帶壞）：

- commit message：有固定格式（type + 主旨），本來就沒有散文
- 程式碼註解：一到兩行，說明「為什麼」，不需要節奏
- 測試案例描述：「應該⋯⋯時回傳⋯⋯」是刻意的公式句，公式就是可讀性
- 表格、條列式規格、API 參數說明：使用者要的就是結構

## 核心原則

每個修辭手段都必須**賺回自己的位置**。對比句要有真對比，排比要有真並列，強調要有真重點。裝飾性的修辭一律刪除。

AI 生成的中文有一組可辨識的統計慣性，合稱「AI 味」。下面每一條單獨看都不算錯，問題是高頻堆疊之後，文件會顯得空洞、像簡報而不像文件，讀者要找的資訊被修辭稀釋掉了。目標不是換一套腔調，是移除慣性，讓內容自己說話。

## 一、限用與禁用

### 1. 「不是 X，而是 Y」假辯證（限用）

只有讀者真的可能誤以為是 X 時才用。若 X 是沒人會主張的稻草人，直接陳述 Y。

- ❌ 這不是單純的樣式調整，而是一次架構層級的重構。
- ✅ 這次重構動到架構層級。
- ✅（正當使用）`useEffect` 的清理函式不是在元件卸載時執行，而是在每次相依項目變動後、下一次 effect 之前執行。（讀者確實常搞錯）

量化規則：每千字至多一次，且要通過稻草人測試：真的有人會相信 X 嗎？

同族變體同理：「並非 X，而是 Y」照同一條規則；遞進式「不僅 X，更 Y」的測試是：只說 Y 有損失嗎？沒有就只說 Y。

### 2. 破折號（限用）

中文破折號（——）的正當功能只有兩個：插入補充語、標示語意的突然轉折。當萬用連接詞用（代替逗號、冒號、「因為」「也就是」）一律禁止。  <!-- zhtw-lint: skip -->

- ❌ 這個 hook 很特別——它同時訂閱兩個 store——這在既有元件中很罕見。
- ✅ 這個 hook 同時訂閱兩個 store，在既有元件中很罕見。

量化規則：每千字至多一組。刪除測試：改成逗號或句號後語意不變，就改。

### 3. 三項式排比（限用）

「更 A、更 B、更 C」「A 性、B 性、C 性」這類三連發，通常是用節奏感掩蓋內容重複。三項若可互相推導，砍到一項。

- ❌ 這個做法更清晰、更精確、更有效率。
- ✅ 這個做法更精確。（清晰與效率是精確的後果，不必列）

### 4. 空轉話語標記（禁用）

以下短語一律刪除，刪後語意不損：「值得注意的是」「更重要的是」「事實上」「毫無疑問」「可以說」「從某種意義上來說」「簡單來說」「總的來說」「綜上所述」。

此表是舉例不是窮盡，同族變體視同禁用：「需要注意的是」「值得一提的是」「有趣的是」「更關鍵的是」。判準一律是：整個短語刪掉，語意不損就刪。

另一族是**標題式套語**，出現在段落或列點的開頭：「一句話：」「核心理念：」「關鍵：」「重點是：」「以下是⋯⋯」。它們在簡報和條列式文件裡特別容易繁殖，因為看起來像在幫讀者導覽，實際上是在宣告下一句很重要。重要的句子靠位置和內容證明自己。

重點不需要宣告自己是重點。若某句真的重要，靠位置（段首或段尾）和篇幅表達，不靠標籤。

### 5. 貼標語彙（禁用）

以下詞彙帶有濃重的機翻或公文腔，右側是替代方向：

| 禁用 | 替代 |
|------|------|
| 賦能 | 讓⋯⋯能夠、給⋯⋯工具 |
| 深入探討 | 討論、分析、細看 |
| 揭示了 | 顯示、說明、指出 |
| 擁抱（抽象物） | 接受、採用 |
| 打造 | 做、建立、寫 |
| 旨在 | 為了、目的是 |
| 至關重要 | 重要、關鍵（擇一，不疊加） |
| 不可或缺 | 必要 |
| 進行 + 動詞 | 直接用動詞（「進行分析」→「分析」） |

中國軟體圈行話（落地、復盤、閉環、抓手⋯⋯）另有一表，見 [SKILL.md](../SKILL.md) 的「中國軟體圈行話禁用表」；那一節在所有任務中都生效，不限散文。

### 6. 結構強迫症（限用）

技術文件天生偏好結構，所以這條在此領域最容易破功。判準是：結構要反映內容的形狀，不是拿來排版。

- **分點列項**：只在內容真正並列且超過三項時使用。兩三個相關的點，寫成一段話。
- **加粗**：每段至多一處，且只用於讀者掃讀時必須抓住的詞。整句加粗一律禁止。
- **小標題**：千字以內的文件不設小標題。
- **段尾微型總結**：不要每段結尾都收一句「因此⋯⋯」「這說明⋯⋯」。一篇文件只在真正的結尾總結一次，或者不總結。
- **Emoji**：不主動加。標題與列點前的裝飾性 emoji 一律省去；只在使用者自己先用或明確要求時跟用。功能性符號例外：`⚠️` 標警告、`⭐` 標推薦、流程圖的節點標籤，這些帶資訊，不算裝飾。

### 7. 開場與收場公式（禁用）

- 不復述問題開場：「這是一個很好的問題」「關於 X，我們可以從幾個方面來看」。直接進入內容。
- 不用應答式熱情開場：「當然可以！」「好的，沒問題！」。答不答應，從做不做看得出來。
- 不用展望式收尾：「未來值得持續關注」「希望這些資訊對你有幫助」「總而言之，X 是一個複雜而迷人的領域」。內容說完就停，好的結尾是最後一個有內容的句子。

### 8. 自問自答（限用）

「這意味著什麼？」「為什麼會這樣？」這類修辭性設問，每篇至多一次，且答案必須不是顯而易見的。

### 9. 贅詞「一個」（限用）

英文冠詞 a/an 的殘影；「一種」「一位」「一項」同理。量詞留給真正計數、或首次引入而需要個體化的場合。

- ❌ 這是一個值得重構的模組。
- ✅ 這個模組值得重構。

刪除測試：刪掉量詞短語後句子仍通，就刪。

### 10. 框式介詞（限用）

「在⋯⋯的過程中」「在⋯⋯方面」「在⋯⋯上」「對⋯⋯而言」「⋯⋯的情況下」：英文介詞片語（in the process of, in terms of）的直譯框。拆框留核。

- ❌ 在重構的過程中，我們在效能方面遇到困難。
- ✅ 重構時我們卡在效能。

正當使用：框內成分長到非框不能斷句時保留。

### 11. 引號（限用）

引號的本職不受限：提及而非使用（把「值得注意的是」當標本引用）、術語首次標示、直接引文、篇章名。中文沒有斜體可用，這些場合「」是唯一的提及記號。

AI 味的是另外三種，禁用或改寫：

- **強調性引號**：這點「很」重要。強調靠句法與位置，不靠標點。
- **裝飾抽象概念**：這股「慣性」、那種「氛圍」。概念不需要穿衣服，拿掉引號。
- **距離性引號**：對自己選的詞沒把握，用引號先道歉。通過刪除測試：拿掉引號語意不變也不生歧義，就拿掉；拿不掉表示詞不準，該換詞，不是加引號。

「所謂」與引號擇一，「所謂的『規範』」是雙重標記。

技術寫作補充：程式碼符號、檔名、路徑用反引號，不用「」。這是 SKILL.md 的規則，優先於本節。

## 二、正向原則

刪掉慣性之後，靠什麼寫？

1. **動詞驅動**。中文的力量在動詞。名詞化的英文結構（the implementation of, the analysis of）還原成動詞句。
2. **短句節奏**。長句若含三個以上邏輯層，拆開。但不要機械地全用短句，長短交錯才有節奏。
3. **具體優於抽象**。「這個做法有很多好處」是空話；「這個做法讓首屏少載 40 KB」是內容。寫不出具體版本，通常表示這句話本來就不必寫。
4. **信任讀者**。不解釋顯而易見的事，不重複已說過的話，不在句尾追加保險性的限定語（「當然，這也取決於具體情況」）。
5. **有立場**。並陳選項之後要選邊：「兩者各有優劣，取決於需求」是把決定丟回給讀者。給出建議與理由，讓讀者有具體的東西可以同意或反對。（涉及事實不確定時，誠實標注不確定性優先於表態。）

## 三、產出前自我檢查

寫完初稿後逐項掃描，不要籠統重讀。籠統重讀抓不到慣性，因為慣性讀起來很順，那正是它的問題。

1. 搜尋「——」：超過每千字一組嗎？每一處通過刪除測試了嗎？  <!-- zhtw-lint: skip -->
2. 搜尋「不是」「並非」「不僅」：每個對比句與遞進句通過稻草人測試了嗎？
3. 搜尋第 4、5 條的禁用詞：「值得注意」「需要注意」「事實上」「深入」「揭示」「賦能」「進行」「至關重要」。同族變體一併抓。
4. 搜尋「一個」「一種」「過程中」「方面」：通過第 9、10 條的刪除測試了嗎？
5. 檢查每段結尾：有沒有微型總結？有沒有兩段以上用同樣的句式收尾？
6. 檢查開頭與結尾：開場有沒有復述問題或應答式熱情？收尾有沒有停在最後一個有內容的句子？有沒有自己加上的 emoji？
7. 引號掃描：不屬於提及、術語首現、引文、篇章名的引號，通過第 11 條的刪除測試了嗎？
8. 朗讀測試：挑最長的一段默唸，任何讓你換氣困難、或聽起來像簡報旁白的句子，改寫。

兩道可以直接跑的 grep，都必須零命中：

```bash
grep -nE '——|一句話|核心理念|關鍵：|以下是' <file>
grep -nE '數據|組件|異步|加載|緩存|服務器|依賴|模塊|代碼|對象|數組|函數|變量|網絡|默認|用戶' <file>
```

改整份文件的風格時，先重讀現狀再一次整檔覆寫，不要散落幾十處小修。風格要一致，逐處修改會留下前後不一的句子。

若使用者說仍有 AI 味，把該例納入本次對話的臨時禁用清單，重跑本節。

## 例外

- 使用者明確要求條列、摘要、表格時，第 6 條讓位。
- 引用外部文件或規格原文時，原文的修辭結構優先。
- 本檔管的是「慣性」，不是「禁止修辭」。一個賺回自己位置的破折號、一組真正的排比，永遠歡迎。
